## 二、统一视觉规则

奶油白纸张做底，浅橡木做棋盘和收纳区，玫瑰粉突出主要操作，灰豆绿表示可交付或完成，香槟金只用于奖励。背景、人物、物品保持同一种水彩笔触；阴影遵循各房间实际窗户光源。

标题略有手写感；数量和说明优先清晰。正式界面全部文字、数量与按钮由 Cocos 渲染，纹理和插画单独制作。保留顶部安全区、底部手势区和足够的触摸面积。按压、选中、不可用、冷却、奖励到账使用统一状态样式，减少同时播放的装饰动画。

## 三、实体生成器：拟采用的交互与规则

### 布局

主棋盘改为 **7列×9行，共63格**，生成器和普通物品占用同一块棋盘；取消早先提出的独立生成器抽屉。新档初始开放9格的既有要求暂保留，新增行列的逐级解锁方案在实施时写入配置。概念图展示全部63格开放的示例状态。棋盘横向接近满宽，保留奶油白、米色底和浅木边框，不采用参考图的蓝色。备齐物品所在格使用浅豆绿，并放置清晰的大绿勾。

生成器在主棋盘格内移动、生产和合成。可以拖进普通背包，每台占一个已开放的背包格，取回时保留自身状态；生产与合成需要取回棋盘。领取奖励与购买时直接放入主棋盘空格。单击生成器生产、长按查看等级和产出、拖动移动；同类型同等级拖到一起可合成。所有操作必须避免短拖被误识别为生产。

左上角放头像、等级和经验进度；体力、金币、钻石在顶部横排，商店放在右上区域并避开微信胶囊。三位顾客以大半身人物为主体，需求放在人物前方托盘，金币和经验奖励放旁边，备齐后居中显示交付按钮。底部采用左背包、中间物品说明、右回家园；任务和回忆从家园进入。人物和物品使用原创小屋插画，参考商业截图的布局与反馈，不复用其角色和素材。

### 获取和成长

任务、等级礼包和章节奖励可给出实体生成器副本，领取后直接落在主棋盘空格，不覆盖现有机器。没有空格时保留奖励未领取，提示先腾位置；不把生成器发往背包或任何储存区。生成器等级沿用现有 1–8 级上限；最低产出随生成器等级提高，高级产出权重与冷却成长沿用既有配置。普通生成器 60 次额度、橘树 10 次额度和基础每分钟恢复一次的既有规则在改版中保留。

每个生成器单独保存 UID、种类、等级、剩余额度、恢复时间和主棋盘位置。不得共用一份冷却后又表现为多台机器；移动、合成及重启不得凭空恢复次数。合成后的额度和恢复时间必须采取可验证的保守换算，规则实施前写入配置与测试。

### 存档迁移

拟在实施阶段由当前 v8 迁移至下一版；实施前重新核对实际版本。旧的生成器库存和已启用生成器转换为主棋盘实体，保留等级、实际额度缺口与冷却。不能把同一份已有剩余额度复制给所有副本，也不能重复发放新手机器。坐标冲突或空间不足的旧机器保留为未领取的迁移补发奖励，腾出棋盘位置后领取，不能形成可任意存入取出的生成器仓库；奖励领取状态、货币、背包及故事进度保持完整。

订单以已拥有的生成器作为来源，收纳机器时保留现有需求和奖励；备货卡可直接打开背包并选中机器。机器升级后仍需核对旧订单的可达性，保留订单身份与奖励。

## 四、落地顺序

### 背包扩容补充（2026-11-18）

初始6格，钻石逐格购买扩容，最高6×6共36格。价格随已扩容格数递增并由配置驱动；效果图中的10钻仅为示意，正式费用在实施时结合钻石获取核定。界面显示当前容量、36格总上限、下一格费用和明确确认按钮。钻石不足和达到上限时有可见状态。扩容通过GameContext原子扣费并解锁，防止重复点击多扣、超限或重启丢失；旧档已购买容量需完整保留。

除原列验收外，需补测初始6格、逐格扣钻、余额不足、36格上限、重复操作和旧档迁移。背包物品仍静止、不参与合成或生产。

1. **视觉方案（本轮已完成）**：29张主要页面与状态图、合成页修订、背包36格方案、提示词清单和可放大方案册。检查了PNG可读性、页面结构和主要交互说明；不代表游戏实现或真机验收。
2. **公共组件与素材拆分**：整理颜色、字号、间距、状态及动效；制作可复用纸卡、木框、格子、按钮和阴影，壁画采用独立作品。控制资源尺寸和图集，先留足微信主包余量。
3. **合成与实体生成器**：先做纯 TS 数据模型、棋盘扩容迁移、获取、移动、合成、独立恢复和异常恢复，再接入 Cocos 的棋盘及来源引导。UI 不直接修改存档。
4. **家园和其余页面**：接入家园材质、壁画、家具和编辑器，再推广到回忆、背包、任务、签到、补给、详情、设置和六章解谜。
5. **回归与候选包**：完成逻辑测试、触摸 QA、Creator Web Mobile/微信构建和独立包体检查。新包以正常节奏连续玩 20–30 分钟，记录订单提示频率、误触、空间选择和橘树节奏，再做真机复验。

## 五、验收重点

- 棋盘7×9不变形、初始9格、锁格和触摸区域一致；可产出的生成器都占用主棋盘格子，收纳走普通背包。
- 生成器获得、合成、移动、普通背包收纳取回、满盘领取阻止、取消拖动、重启和旧档迁移无丢失或重复。
- 多台机器的额度与计时各自正确；移动和合成不能刷额度。
- 按钮各状态、订单交付与资源确认反馈明确；图鉴和未解锁故事不泄露。
- 普通合成物可在详情里单件出售，预先显示售价；出售会使备齐订单缺货时应提示。确认后只清除选中格，金币到账与空格均保留到重启后。
- 家具阴影、壁画透视与场景一致；撤销、对齐及缩放继续可用。
- 小屏、长屏、安全区、后台恢复和照片路径在真实构建中验证。
- 运行 `test:core`、`lint:core`、`build:web`、`verify:cocos` 及对应新增检查；未实际执行的构建和真机项目不得记为通过。
